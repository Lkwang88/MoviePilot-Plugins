# 小仓酱的订阅优先整理 (OguraTransferPriority)

订阅下载的媒体在 MoviePilot 整理队列中**插队到队首优先整理**，手动及其他任务保持原有先来后到顺序。适合 HDD 大盘机：订阅想尽快看，手动任务慢慢搬。

## 原理

MP v2 的整理队列是标准 FIFO（`TransferChain._queue`），无优先级概念。本插件把该队列**原地升级**为优先队列：

- **P0**：订阅任务——下载历史 `note.source` 以 `Subscribe|` 开头
- **P0.5**：在插件数据页点击“手动插队”的普通任务——只影响仍在等待的任务，且不越过订阅
- **P1**：手动下载 / 其他来源 / 识别失败的兜底
- 同级内严格按入队顺序（FIFO），绝不乱序

### 零破坏设计

- 排序键为 `(优先级, 全局递增序号)`，比较永不触达任务对象本身
- 迁移时先替换引用再吸收存量，任务零丢失；正在整理中的任务不受影响
- 手动插队在队列锁内原地修改优先级并 `heapify`，不 `get`、不 `put`、不修改 `unfinished_tasks`
- 判定函数全链路 try/except，任何异常一律按 P1 普通处理，绝不影响整理主流程
- 停用插件时自动进入降级模式；不交换队列引用，避免生产者并发入队丢任务
- MP 重启后插件自动重新生效（队列随重启回归原生，运行时手动优先状态自然清除）

## 数据页

插件详情页按“媒体身份 + 季号”合并展示当前任务，包含等待中和正在执行的任务，并合并显示集数。

- 媒体身份优先使用 MP v2 官方 `resolve_media_identity`；无 ID 时才使用标题+年份兜底
- 同一剧集同一季合并为一个项目；不同季分开；电影作为一个项目
- 页面显示正在整理数、等待数、订阅数、普通数和集数范围
- “刷新队列”按钮重新加载页面；页面是打开/刷新瞬间的快照，不做自动轮询
- “手动插队”只提升该项目仍在等待队列中的非订阅任务，正在整理的任务不打断
- 插队后的顺序为：订阅 → 手动插队 → 其他普通任务
- 手动优先级是运行时临时状态，不写数据库，MP 重启后自动清除

### 通知

走插件消息通道（`NotificationType.Plugin`）：

- 生效通知：插件启用 / 队列切换完成
- 迁移通知：切换时队列有存量任务时播报迁移数量
- 插队通知：订阅任务实际插队到 N 个普通任务前（同一种子只提醒一次，防多集刷屏）

## 配置

| 配置项 | 默认 | 说明 |
|--------|------|------|
| enabled | false | 启用插件 |
| notify | true | 生效/迁移通知 |
| notify_jump | true | 插队通知（每种子一次） |

## 兼容性

MoviePilot v2（基于 **v2.15.6** 开发验证）。升级 MP 若队列结构变更，插件会探测到不兼容：核心整理功能不受影响，数据页进入只读降级并禁用手动插队。
